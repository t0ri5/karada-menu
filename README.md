# からだ想い献立 v3 — 毎朝更新付き PWA

町屋周辺の3店舗の公開情報を確認し、特売食材と献立を組み合わせるWebアプリです。2026年10月18日からの30日分の献立を収録しています。

**[公開アプリを開く](https://t0ri5.github.io/karada-menu/)** ／ [更新処理の実行履歴](https://github.com/t0ri5/karada-menu/actions/workflows/daily.yml)

## 主な機能

- 朝・昼・夕の献立案、30種類の夕食レシピと2人分の材料を表示。肉・肉エキス・シイタケ不使用の献立で、魚介は使用します。
- 3店舗のチラシ・店舗ページへのリンクと、確認できた特売商品を表示。
- 特売の手入力メモ、食材との献立マッチング、買い物リスト、人数変更、オフライン機能。
- 献立候補は一致する食材の種類が多い順に選択。容量・単位をそろえた最安値比較は未対応です。

## チラシ・商品取得の対応状況

**チラシの掲載期間確認と、商品名・税込価格の取得は別の処理です。画像チラシの商品読取り（OCR）は未対応です。**

| 店舗 | チラシ掲載期間の確認元 | 商品名・税込価格の取得 |
| --- | --- | --- |
| コモディイイダ 町屋店 | 公式店舗ページを優先。確認できない場合はチラシガイド | トクバイの当日テキスト掲載分のみ。画像読取りは未対応 |
| オリンピック 荒川一丁目店 | Shufoo!を優先。確認できない場合はチラシガイド | トクバイの当日テキスト掲載分のみ。画像読取りは未対応 |
| TAIRAYA 町屋店 | トクバイへのリンクを表示。チラシ期間の自動確認は未対応 | トクバイの当日テキスト掲載分のみ |

商品は「今日の掲載」から、`scripts/update_deals.py` の `KEYWORDS` に一致し、`EXCLUDE` に一致しない食材を抽出します。本日分の自動取得データだけを献立候補に使います。3店舗の全商品取得・毎日の取得成功・最安値は保証しません。

## スマートフォンで使う

1. [公開アプリ](https://t0ri5.github.io/karada-menu/)を開きます。利用者のGitHubログインは不要です。
2. AndroidのChromeではメニューから「アプリをインストール」または「ホーム画面に追加」を選びます。
3. 「3店舗のチラシ・特売」で取得日と店舗別の状態を確認します。商品が0件の場合はチラシを開き、必要な特売を手入力できます。

手入力メモ・買い物リストは端末のブラウザー内に保存され、家族や別端末とは同期しません。オフライン時には新しい特売データを取得できません。

## 自動更新と公開

`.github/workflows/daily.yml` が毎日 **08:00 JSTごろ**（UTC 23:00）、`main`への変更時、手動実行時に動きます。予約実行はGitHub側の都合で遅延・停止する場合があります。

1. 日付表記、店舗の確認、過去チラシの除外などの回帰テストを実行。
2. `scripts/update_deals.py` が店舗別の取得結果を `data/latest.json` に出力。
3. 取得済みJSONを診断用アーティファクトとして7日間保存。
4. `site/` に公開用ファイルを組み立て、実行ごとに異なる `data/runs/<build_id>.json` を作成。
5. GitHub Pagesに公開し、公開先JSONの `build_id` が今回の実行と一致するか再試行付きで確認。

生成データは公開用アーティファクトに含まれ、リポジトリの `data/latest.json` には自動コミットされません。公開データは[公開先のlatest.json](https://t0ri5.github.io/karada-menu/data/latest.json)で確認してください。

**Actionsの成功は、全店舗の商品取得の成功を意味しません。** 店舗別の `stores[].status` / `count` と、チラシの `flyers[].status` / `item_extraction_status` を別々に確認します。

| 対象・状態 | 意味 |
| --- | --- |
| 商品：`ok` | 対象商品の品名・税込価格を1件以上抽出 |
| 商品：`no_extractable_offers` | ページを取得し当日の日付を確認したが、条件に合う商品を抽出できなかった |
| 商品：`date_unverified` | 当日の掲載日を確認できず、価格を採用しなかった |
| 商品：`fetch_failed` | HTTPエラーや接続失敗などで取得できなかった |
| チラシ：`current` | 掲載期間に取得日が含まれることを確認。商品取得成功は意味しない |
| チラシ：`expired` / `not_started` | 掲載期間が終了済み／開始前 |
| チラシ：`date_unverified` / `store_unverified` / `unverified` | 日付、対象店舗、または取得元を確認できなかった |
| 画像商品：`unsupported_image_extraction` | 画像チラシからの商品名・税込価格の読取りは未対応 |

### 手動更新・別リポジトリでの公開

- 既存の公開先を更新する場合は、Actionsの `Daily supermarket flyer update and app deployment` → `Run workflow` で `main` を選びます。
- 別リポジトリに配置する場合は、`.github` を含むファイル一式を配置し、`Settings` → `Pages` → `Source` を **GitHub Actions** に設定します。公開先URLはそのリポジトリの設定画面で確認してください。

## ローカルで確認する

Python 3.12を使用し、リポジトリのルートで実行します。

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/update_deals.py
```

Windowsなどでタイムゾーンデータがない場合は、追加で `python -m pip install tzdata` を実行してください。取得処理にはインターネット接続が必要です。

## 制限

- 公開ページの構造変更・アクセス制限・掲載内容によって取得できなくなります。403等の拒否は取得失敗とし、制限を回避しません。
- 商品が取得できない場合は通常献立を表示します。実売価格・対象日・容量・在庫は掲載元や店頭で確認してください。
- 献立・材料量は概算です。栄養成分の自動計算や医療用の食事指導は実装していません。
